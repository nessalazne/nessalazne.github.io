## Why Clone an Existing App?

Building from scratch is slow and expensive. When you clone an existing app, you already know the product works — someone paid $800K to prove it. Your job is to replicate the core value, ship fast, and iterate.

This approach is perfect for:
- **Creators** building niche tools for their audience

- **Marketers** who need custom internal tools, fast

The secret weapon? Claude Code — Anthropic's AI coding agent that turns plain-English instructions into fully functional code.

## Phase 1: Pick Your Target App

The best apps to clone are ones with a clear, simple user flow: input → process → output. Scheduling tools, booking systems, form builders, and simple dashboards are all perfect starting points.

For this tutorial, I cloned a scheduling tool with booking logic, availability management, and email confirmations — the kind of feature set that would cost $50K+ to build traditionally.

**What to look for in a target app:**
- A login → dashboard → core action flow (3 screens or fewer to start)
- A clear value proposition you can describe in one sentence
- Public-facing UI you can screenshot for reference

Don't try to clone every feature at once. Pick the 20% of functionality that delivers 80% of the value and ship that first.

## Phase 2: Scaffold the App with Claude Code

Open Claude Code (or Antigravity IDE) and write a single, detailed prompt describing what you want to build. Be specific about the tech stack, the key user flows, and the problem it solves.

Here's the kind of prompt that works:

> *"Build a scheduling app with React and Node.js. Users should be able to create an availability calendar, share a booking link, and receive email confirmations. Model it after a Calendly-style workflow."*

Claude Code generates the full project structure — folder layout, components, API routes, database schema — in seconds. What used to take a senior developer a week now takes a few seconds of AI thinking.

**Tips for a stronger scaffold prompt:**
- Paste a screenshot of the app you're cloning for visual context
- Name the specific pages: Landing, Dashboard, Booking Page, Confirmation
- Specify your stack (React, Next.js, Supabase, etc.) so Claude doesn't guess

## Phase 3: Iterate Fast with AI

Once the scaffold is live, you iterate by describing what you see — not what you want to code. This is the core of Vibe Coding: you direct, Claude builds.

See a misaligned button? Say: *"The book button should be full-width and centered below the calendar."* Claude fixes it instantly.

Getting a database error? Screenshot it, paste it into Claude, and watch it diagnose and resolve the issue — often in under 30 seconds.

## Phase 4: Ship Without a Dev Team

Once you're happy with the core experience, deploy in one command. I use Vercel — it connects to your GitHub repo and auto-deploys on every push.

The entire cycle — idea → scaffold → iterate → live URL — runs in 15 minutes. No DevOps. No waiting on contractors. No $800K budget.

**The deployment workflow:**
1. Push to GitHub: `git add . && git commit -m "v1" && git push`
2. Connect repo to Vercel (one-time setup)
3. Every subsequent push auto-deploys — share the link immediately

Add a waitlist or email capture on day one. Even if the product isn't perfect, start collecting your audience while you keep building.
